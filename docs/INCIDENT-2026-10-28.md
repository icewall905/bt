# Homepage latency, 2026-10-28

The host had available RAM and disk, all BetterTube services were running, and
health checks responded in about 1 ms. Traefik added about 35 ms. Homepage data
requests took 1.1 s (Family), 1.3 s (Far), and 2.0 s (Eveningfun).

Profiling a live Far homepage request attributed 3.01 of 3.12 profiled seconds to
`order_playlist`: 133,276 similarity comparisons, repeatedly parsing the same
metadata and ordering the entire queue before slicing it to 24 entries.

The fix caches metadata and pair similarities within each ordering call and
stops greedy selection after the requested page boundary. Every choice still
considers all remaining candidates. Regression tests compare full and partial
results against the original algorithm, including autoplay history. API and
playlist tests: 23 passed.

Deployed only the playlist module and the category-feed ordering call, preserving
other existing local and production edits. Production backup:
`/root/compose/bt-healthfix-20261028-150126`. Updated production source, rebuilt
`bettertube:latest`, and recreated only `bt-api`.

Immediately after the initial fix, HTTPS homepage data responses for the same
profiles took 0.29 s, 0.22 s, and 0.36 s. No database or settings changes.
